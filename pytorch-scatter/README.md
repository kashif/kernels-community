## pytorch-scatter

Scatter, segment and gather kernels from
[pytorch_scatter](https://github.com/rusty1s/pytorch_scatter) by Matthias Fey.

Copyright (c) 2020 Matthias Fey. Licensed under the MIT license.

The kernel sources are taken from upstream unchanged; only the operator
registration is adapted, so that the operator namespace is generated by
`kernel-builder` instead of being hardcoded to `torch_scatter::`.

Built for `cpu`, `cuda` and `rocm`. The ROCm variant compiles the same CUDA
sources via hipify, which is what makes this useful: upstream publishes no
ROCm wheels, so AMD users currently have to build the extension from source.

## Usage

The Python API mirrors upstream's signatures exactly, so callers can switch
from `torch_scatter` to this kernel without changing any call sites:

```python
import torch
from kernels import get_kernel

pytorch_scatter = get_kernel("kernels-community/pytorch-scatter")

src = torch.randn(10, 6, 64, device="cuda")
index = torch.tensor([0, 1, 0, 1, 2, 1, 0, 2, 1, 0], device="cuda")

out = pytorch_scatter.scatter(src, index, dim=0, reduce="sum")
print(out.size())  # torch.Size([3, 6, 64])

# `min`/`max` additionally return the argmin/argmax, which the native
# `torch.scatter_reduce` does not provide:
values, argmax = pytorch_scatter.scatter_max(src, index, dim=0)
```

For pre-sorted indices, the CSR and COO segment variants are faster:

```python
indptr = torch.tensor([0, 4, 8, 10], device="cuda")
out = pytorch_scatter.segment_csr(src, indptr, reduce="sum")
```

## Exported operators

| Operator | Notes |
| --- | --- |
| `scatter` / `scatter_{sum,add,mul,mean,min,max}` | unsorted index |
| `segment_csr` / `segment_{sum,add,mean,min,max}_csr` | sorted, index pointers; fully deterministic |
| `segment_coo` / `segment_{sum,add,mean,min,max}_coo` | sorted index |
| `gather_csr`, `gather_coo` | inverse of the segment reductions |

## Notes on scope

Only the compute kernels and their thin operator wrappers are packaged here.
The pure-Python composites that upstream also ships (`scatter_softmax`,
`scatter_logsumexp`, `scatter_std`) are not included: they are built entirely
on top of the operators above and belong in the calling library.

Note that recent PyTorch versions cover the `sum` and `mean` reductions well
via `torch.scatter_reduce` and `torch.segment_reduce`. The reductions that
still have no native equivalent are `min`/`max` **with the accompanying
argmin/argmax**, along with the CSR/COO segment layouts.
